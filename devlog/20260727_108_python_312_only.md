# Devlog 108: One Python Version

**Date:** 2026-07-27
**Current Version:** 0.2.3-beta.2
**Status:** ✅ 3.12 only, end to end; mypy gating unblocked as a side effect
**Previous:** [devlog 107 - The Manual Gets Its Own Directory](./20260727_107_manual_moved_to_docs_manual.md)

---

## 🎯 Overview

The CI matrix was 3 operating systems x up to 3 Python versions. It is now
3 operating systems x 3.12, and the declaration follows the matrix:
`requires-python`, the ruff and mypy targets, the lockfile floor, the badges and
the manual all say 3.12.

---

## 🤔 The argument

Not "3.11 is old". The argument is that **neither group of users is exposed to
the difference**:

- Someone **building from source** sets up their own environment and can make it
  3.12. That is a one-line ask of a person who is already installing a Rust
  toolchain and a Qt stack.
- Someone **installing a release** gets a PyInstaller bundle with its own
  interpreter. They never pick a Python version, and the one we build with is
  the one they run.

So a three-version sweep was paying — in CI minutes and in matrix bookkeeping —
to protect against a risk nobody actually carries. Cutting it takes the quick
matrix from 7 test jobs to 3 and the smoke matrix from 6 to 3.

The important half is the second one: **the declaration follows the matrix.**
Keeping `requires-python = ">=3.11"` while testing only 3.12 would have been the
worst of both — a support claim nobody checks. `pyproject.toml` now carries the
reasoning next to the constraint, so the next person to widen it knows what they
are re-buying.

## ⚠️ Raising the floor does not move the pins

Worth recording because it contradicts what I said out loud an hour earlier.

The expectation was that moving the lock floor from 3.11 to 3.12 would bring
back numpy 2.5.1 and scipy 1.18.0 — the versions the old universal lock carried
above 3.12. It did not. `make lock` writes over the committed lockfile, and
`uv pip compile` **prefers versions already pinned in its output file**. That is
the same property the `lock-check` seeding relies on, and it works in both
directions: the floor allowed 2.5.1, and the resolver kept 2.4.6 because 2.4.6
was already written there.

Getting the intended result took saying so explicitly:

```bash
uv pip compile ... --upgrade-package numpy --upgrade-package scipy ...
```

across all nine locks. A targeted, reviewable upgrade — not `--upgrade`, which
would have moved everything at once and buried the two packages this change was
actually about.

**A version floor is a constraint, not an instruction.** Relaxing a constraint
never moves anything on its own.

## 🎁 mypy gating fell out of it

`TODOs.md` item #2 has carried one `|| true` for weeks: mypy ran advisory in CI
because its config pinned `python_version = 3.11`, and the numpy 2.5 stubs use
3.12 `type` syntax, which a 3.11-configured mypy rejects. The recorded fix was
"bump python_version or scope-exclude numpy".

Bumping it was already part of this change. Running the exact CI command
afterwards, against the locked mypy 1.20.2 and the freshly upgraded numpy
2.5.1:

```
Success: no issues found in 24 source files
```

So the blocker is gone. **The `|| true` was left in place** — this change was
about narrowing the matrix, and turning a new gate on inside it would have meant
that a later mypy failure and this commit were tangled together. It is a
one-word change, recorded in `TODOs.md` with the evidence, for whenever it is
wanted on its own.

## 💡 Lessons

1. **Support is a claim, and claims need a test behind them.** The matrix and
   `requires-python` disagreeing is not a cosmetic inconsistency; it is
   promising something no job verifies.

2. **Ask who is exposed to the risk.** The case for dropping 3.11 was not about
   the version. It was that source users control their environment and release
   users get a bundled interpreter — so nobody was being protected by the
   third matrix axis.

3. **Relaxing a constraint changes nothing by itself.** The floor moved; the
   pins did not. I had said they would. Lockfiles prefer what is already
   written in them, by design.

4. **Let a freed-up gate stay closed until its own commit.** mypy passes now,
   and enabling it here would have made a later type error look like a
   consequence of a Python-version change.
