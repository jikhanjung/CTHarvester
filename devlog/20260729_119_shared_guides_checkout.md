# 119 — 공통 가이드를 복사하지 않고 참조하기로, 그리고 이 저장소에 없던 CLAUDE.md

2026-07-29. 코드 변경 없음. 바뀐 것은 **형제 프로젝트가 공유하는 규약을 어디서 찾느냐**이고,
답은 의도적으로 "이 저장소 안"이 아니다.

## 이 저장소는 이미 같은 일을 하고 있었다 — 더 나쁜 형태로

새로울 것이 없다는 점부터 적어 둔다. `TODOs.md:9`는 이렇게 시작한다:

    Live status against `../Modan2/docs/CODE_QUALITY_GUIDE.md` (v1.0, 2026-07-23)

devlog 100·103도 같은 경로를 참조한다. **형제 저장소에 있는 문서를 상대경로로 가리키는
방식은 이 저장소가 이미 석 달 가까이 쓰고 있던 것**이다. 그리고 그 링크도 Modan2가 옆에
체크아웃돼 있어야만 풀린다 — 지금 도입하는 심볼릭 링크와 성질이 같은데, **그 사실이 어디에도
적혀 있지 않았을 뿐**이다.

달라지는 것은 **소유자**다. 옛 형태는 *한 형제 프로젝트가 자기 저장소에 둔 사본*을 가리킨다.
새 형태는 **어느 프로젝트에도 속하지 않는 공유 묶음**을 가리키고, 그 묶음의 소유자는 하나다.

## 왜 복사가 아니라 참조인가

공유 가이드 묶음은 원래 첫머리에 *"이 디렉터리를 프로젝트 `docs/`로 복사해 계약으로
채택하라"*고 적고 있었다. 이식용 표준이라면 당연한 문장이다.

그런데 **가이드가 작성된 다음 날 그 실패 모드가 원본에서 나왔다.** 파일 위치 가이드가
일반화한 상류 계획에 저장소 분할 권고(미디어는 `Documents`, DB는 로컬 고정)가 들어 있었는데,
하루 뒤 상류가 개정되면서 **그 절충안이 철회됐다.** DB 없는 데이터 디렉터리는 객체 id로
이름 붙은 파일 더미라 백업되는 절반의 복구 가치가 0이라는 이유였다.

가이드는 알 수 없었다. 스냅샷을 일반화한 문서인데 스냅샷이 움직였기 때문이다. **가이드는
자기가 일반화한 대상보다 먼저 낡을 수 있고**, 하필 낡은 부분이 배경이 아니라 **"이렇게
하라"는 권고 문장**이었다. 복사한 프로젝트 수만큼 낡는 시계가 늘고, **사본은 자기가 낡았다고
알려 주지 않는다.**

그래서 `.guides/`는 심볼릭 링크다. 갱신은 체크아웃에서 `git pull`이고, 소유자가 하나이므로
이 드리프트가 권고 사항이 아니라 **구조적으로 불가능**해진다. `.gitignore`가 덮는다 —
가이드는 비공개이고 이 저장소는 공개라, 커밋하는 것은 물론 `docs/`로 복사하는 것도 곧
공개다(검토했다가 접은 발행안과 같은 결과).

## CLAUDE.md를 새로 만들었다

**이 저장소에는 CLAUDE.md가 없었다.** 형제 프로젝트들과 다른 조건이고, 여기서 걸렸다 —
링크가 `.gitignore`되므로 **있다는 사실을 알릴 것이 없다.** 포인터 없이 링크만 걸면 발견
경로가 없어 아무 일도 일어나지 않는다.

대안으로 `CONTRIBUTING.md`를 봤지만 맞지 않았다. 546줄짜리 **외부 기여자용 공개 문서**이고,
그 체크아웃을 영영 가질 수 없는 사람들에게 하는 안내가 된다.

그래서 CLAUDE.md를 만들되 **라우팅 역할**로 한정했다 — 규약이 저장소 밖에 있다는 것과,
이미 있는 문서들이 각각 무슨 일을 하는지(`CONTRIBUTING.md` = 개발 워크플로 / `TODOs.md` =
계획 / `devlog/` = 기록 / `CHANGELOG.md` = 출하된 것 / `VERSION_MANAGEMENT.md` = 버전).
**내용을 새로 지어내지 않고 있는 것을 가리키기만 하므로** 틀릴 여지가 적고, 나중에 제대로
채우려면 그 위에 얹으면 된다.

## 다른 머신에서 거는 법

체크아웃은 비공개 문서 저장소의 **부분·희소 클론**이다. `guides/`만 받는다.

```
git clone --filter=blob:none --sparse <devdocs>
cd devdocs && git sparse-checkout set --no-cone '/guides/'
ln -s ../devdocs/guides .guides      # 형제 프로젝트 디렉터리에서
```

세 가지가 결정적이고 **셋 다 한 번씩 틀린 뒤에 알았다**:

- **`--no-cone`이 필요하다.** cone 모드는 각 상위 단계의 파일을 **항상** 포함하므로 저장소
  루트 파일이 딸려 온다. 용량(수십 KB)이 아니라, `guides/`만 있는 체크아웃 옆의 파이프라인
  스크립트가 **돌릴 수 있는 것처럼 보이는** 게 문제다.
- **패턴에 앞의 `/`가 필요하다.** non-cone은 gitignore 스타일이라 `guides`는 **경로 어디에
  있든** 매칭된다 — 아카이브 안에 중첩된 무관한 `guides/`가 실제로 딸려 왔다. `'/guides/'`가
  루트에 앵커한다.
- **심볼릭 링크 대상은 상대경로로.** 절대경로는 머신마다 다르다(형제 프로젝트들이 놓이는
  위치가 기계마다 다르다). WSL에서 Windows 드라이브 위에 걸어도 동작하며, Windows는
  절대경로를 junction, 상대경로를 디렉터리 심볼릭 링크로 본다.

**`--filter=blob:none`은 "안 받는다"가 아니라 "필요할 때 받는다"** 이다. sparse-checkout은
작업 트리만 제한하고 전송은 제한하지 않는다 — `git pull`이 fast-forward 뒤 찍는 diffstat만
해도 그 파일 blob을 끌어온다.

## 열어 둔 것 — 코드 품질 가이드의 기준을 옮길 것인가

`TODOs.md`의 "Code quality guide status" 표는 `../Modan2/docs/CODE_QUALITY_GUIDE.md`의
**Appendix A(우선순위 채택 체크리스트)** 를 추적한다. 공유 묶음에도
`.guides/desktop/code-quality.md`가 있어 기준을 그쪽으로 옮기고 싶어지는데, **지금 바꾸면
추적이 깨진다**:

| | Modan2 원본 | 공유 가이드 |
|---|---|---|
| 절 수 | 14 | 7 |
| Appendix A 체크리스트 | 있음 (표가 추적하는 대상) | **없음** |

같은 계보지만 **같은 문서가 아니다.** 공유본은 재구성·압축된 판이고 체크리스트가 없다.
그래서 이번에는 손대지 않았다. 옮기려면 체크리스트를 공유 가이드에 세우거나 표의 기준을
다시 짜야 하고, 그건 별건이다.

## 바뀌지 않는 것

`core/`도 `ui/`도 빌드도 그대로다. 의존성도 늘지 않았다. 가이드는 여기서 작업하는 사람이
보는 참조 자료이지 프로그램의 입력이 아니다. 이 기록을 남기는 이유는 **`docs/guides/`가
없는 것이 누락이 아니라 결정으로 읽히게** 하기 위해서다.
